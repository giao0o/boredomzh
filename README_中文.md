# 人工拣货无聊成本混合仿真：中文交付包

## 1. 项目简介

本项目是硕士论文主题“人工订单拣选中团队层面无聊成本的仿真研究”的可运行原型。

模型结合两种方法：

- 使用 SimPy 建立离散事件仿真，模拟订单到达、共享队列、拣货、错误、返工和班次结束积压。
- 使用普通 Python 类建立员工智能体，模拟无聊状态、速度下降、错误率上升、非工作对话、同事中断和情绪传播。

研究问题：

1. RQ1：当团队中一定比例的员工处于无聊状态时，会造成多大的团队生产率和成本损失？
2. RQ2：总损失中有多少属于间接损失，即由同事互动、中断和无聊传播造成，而不是无聊员工自身产出下降造成？

> 重要说明：这是研究原型，不是经过验证的生产决策系统。所有行为参数都是尚未经过实证校准的占位参数，默认结果不能直接解释为真实仓库中的无聊成本。

## 5. 模型结构

### 5.1 离散事件层

默认设置：

- 班次长度：8 小时
- 团队人数：8 人
- 一个共享 FIFO 订单队列
- 分时段非齐次泊松到达过程
- 每个订单包含 1 至 8 个订单行
- 每个订单行具有对数正态分布的行走时间和拣取时间
- 每个订单具有固定交接或包装时间
- 每个订单行可能发生错误，错误会产生返工时间和欧元成本

默认每小时需求曲线为：

```text
22, 34, 50, 64, 60, 36, 26, 20 个订单/小时
```

按照默认订单内容和作业时间计算，理论利用率约为：

| 小时 | 订单/小时 | 理论利用率 |
|---:|---:|---:|
| 1 | 22 | 30.3% |
| 2 | 34 | 46.8% |
| 3 | 50 | 68.8% |
| 4 | 64 | 88.1% |
| 5 | 60 | 82.5% |
| 6 | 36 | 49.5% |
| 7 | 26 | 35.8% |
| 8 | 20 | 27.5% |

### 5.2 无聊智能体层

每名员工都有连续无聊状态 `B`：

```text
0 <= B <= 1
```

每分钟使用欧拉法更新一次。概念形式为：

```text
dB = a_up × underload × (1 - B)
     - a_down × utilisation × B
     + contagion × max(0, contacts_mean_B - B) × (1 - B)
```

其中：

- `underload = 1 - 过去约15分钟的滚动利用率`
- 低负荷促进无聊增长
- 工作繁忙促进无聊衰减
- 联系人的平均无聊程度高于当前员工时，可能产生向上的传播效应

每次更新后，`B` 被限制在 `[0, 1]`。

### 5.3 无聊的行为影响

无聊通过以下机制影响作业：

1. 行走和拣取时间乘以 `1 + slowdown_strength × B`
2. 错误概率增加为 `base_error_probability + error_boredom_slope × B`
3. 员工发起非工作对话的频率随 `B` 上升
4. 对话平均持续时间随发起者的 `B` 上升
5. 完整场景中，对话可能占用同事时间
6. 完整场景中，无聊可能通过同事接触传播

## 6. 三个核心场景

### Baseline

- 将无聊固定为 0
- 不发生无聊减速
- 不发生无聊导致的错误增加
- 不发生对话
- 不发生同事中断
- 不发生传播

### Direct Only

- 无聊影响员工自身速度
- 无聊影响员工自身错误率
- 发起对话者损失自己的时间
- 同事不被中断
- 不存在无聊传播

### Full

- 所有自身效应开启
- 对话同事也损失时间
- 空闲同事可以被立即邀请
- 忙碌同事在下一个订单行边界处理邀请
- 无聊传播开启

## 7. 损失分解

```text
直接损失 = cost(direct_only) - cost(baseline)
间接损失 = cost(full) - cost(direct_only)
总损失   = cost(full) - cost(baseline)
溢出比例 = 间接损失 / 总损失
```

当总损失接近 0 时，程序不会强行计算溢出比例。

该分解具有路径依赖性。当前模型先开启个人效应，再开启同事中断与传播，因此个人效应和社交机制之间的交互项会被归入间接损失。论文扩展可使用第二种开启顺序或 Shapley 分解进行稳健性分析。

## 8. 成本定义

### 8.1 产能成本，主要视角

```text
错误数 × 单次错误成本
+ 已完成订单总流动时间 × 每订单分钟延迟成本
+ 未完成订单数 × 未完成订单惩罚
```

该视角能够反映质量、排队、拥堵、延迟和班次结束积压。

### 8.2 有薪时间成本，辅助视角

```text
工资率 ×（对话分钟 + 无聊减速分钟）/ 60
```

该视角接近传统人工成本估算，但不能完整反映队列效应和服务水平损失。

## 13. 自动合理性检查

程序启动时自动检查：

1. 所有无聊效应关闭时，三个场景的关键结果一致
2. 所有无聊状态保持在 `[0, 1]`
3. 每个到达订单都被完成或计入未完成订单
4. 双人对话时间被计入双方参与时间
5. 相同随机种子产生完全相同的结果

检查失败时，程序通过断言停止运行。

## 15. 主要局限性

1. 行为参数尚未经过实证校准。
2. 初始无聊状态由模型外生设定。
3. 当前主要使用滚动利用率表示低负荷。
4. 员工的基础速度和错误风险是同质的。
5. 对话仅被建模为时间损失，没有积极协调或恢复作用。
6. 社交网络结构较为简化。
7. 未模拟仓库路径拥堵、分区、补货和设备限制。
8. 错误被假设为立即发现。
9. 未完成订单使用简化的货币惩罚。
10. 置信区间只表示仿真随机性，不表示全部参数不确定性。
11. 直接和间接损失分解依赖机制开启顺序。
12. 模型尚未使用真实仓库数据验证。

## 16. 论文扩展建议

1. 使用 WMS 时间戳、订单行记录、错误记录和短时无聊问卷校准参数。
2. 使用独立班次验证每小时拣取量、利用率、流动时间和错误率。
3. 使用工作区域、排班、休息重叠或距离传感器建立真实社交网络。
4. 将对话区分为非工作交流、协调、问题解决、培训和安全沟通。
5. 比较工作轮换、任务丰富化、微休息、交叉培训和需求平滑等干预。
